# Отчёт по утечкам памяти

Документ описывает аудит клиента (`packages/client`) на утечки памяти: какие
потенциальные утечки были найдены, как они исправлены и какие места изначально
сделаны корректно.

## Методика

Под «утечкой» в SPA понимаем ресурс, который продолжает удерживаться (или
продолжает работать) после размонтирования компонента: незакрытые таймеры,
неснятые слушатели событий, не отменённые `requestAnimationFrame`, неотписанные
подписки, висящие обработчики на долгоживущих объектах (`window`, `document`,
`Image`), а также detached DOM и неограниченно растущие структуры данных.

Аудит проводился **статическим анализом**: просмотр всех `useEffect` / хуков и
поиск по паттернам (`addEventListener`, `setInterval`/`setTimeout`,
`requestAnimationFrame`, `new Image`, `matchMedia`, `URL.createObjectURL`,
подписки). Для каждого случая проверялось наличие парной очистки в cleanup.

Наибольшее внимание уделено странице игры `/game` (Котосапёр): там сосредоточена
вся динамика — canvas, RAF-анимации, таймер, слушатели мыши и `document`.

## Найденные потенциальные утечки и их исправление

Все три относятся к одному классу: ресурс инициализировался, но не очищался при
размонтировании компонента.

### 1. RAF-анимация ховера не отменялась при размонтировании

- **Файл:** `src/pages/game/hooks/useHoverAnimation.ts`
- **Симптом:** `requestAnimationFrame`-цикл отменялся только при запуске новой
  анимации, но не при размонтировании. Если уйти со страницы `/game` в момент
  активной анимации, цикл продолжал вызывать `drawRef.current()` уже после
  удаления канваса и держал замыкание со ссылками на refs.
- **Исправление:** добавлен unmount-cleanup с `cancelAnimationFrame`.

```ts
useEffect(() => {
  return () => {
    if (rafRef.current) {
      cancelAnimationFrame(rafRef.current)
    }
  }
}, [])
```

### 2. RAF-анимация открытия ячеек не отменялась при размонтировании

- **Файл:** `src/pages/game/hooks/useRevealAnimation.ts`
- **Симптом:** аналогично п.1 — `revealRafRef` отменялся только при старте новой
  анимации открытия. Размонтирование во время fade-in оставляло активный
  RAF-цикл.
- **Исправление:** добавлен отдельный unmount-cleanup с `cancelAnimationFrame`
  для `revealRafRef`.

### 3. Обработчики `Image.onload` / `onerror` не снимались

- **Файл:** `src/pages/game/hooks/useCanvasImages.ts`
- **Симптом:** при предзагрузке svg-иконок создавались `Image` с обработчиками
  `onload`/`onerror`. Если компонент размонтировался до завершения загрузки,
  обработчики оставались и могли вызвать `drawRef.current()` после удаления
  компонента, удерживая замыкание.
- **Исправление:** в cleanup эффекта снимаются обработчики и выставляется флаг
  `cancelled`, чтобы `onSettled` ничего не делал после размонтирования.

```ts
let cancelled = false
const loaded: HTMLImageElement[] = []
// ...
return () => {
  cancelled = true
  for (const img of loaded) {
    img.onload = null
    img.onerror = null
  }
}
```

> Важно: это не «жёсткие» persistent-утечки (анимации живут 60–120 мс, картинки
> после загрузки собираются GC). Это устранение некорректной очистки — работа
> после unmount и лишние замыкания, которые при частой пере-навигации создают
> ненужную нагрузку и шум «setState/draw after unmount».

## Места, изначально сделанные корректно

Аудит подтвердил, что подавляющее большинство потенциально «текущих» мест уже
закрыты правильно — отдельных исправлений не потребовалось:

| Где | Ресурс | Очистка |
|-----|--------|---------|
| `pages/game/ui/GamePage.tsx` | `setInterval` игрового таймера | `clearInterval` в cleanup |
| `pages/game/ui/GamePage.tsx` | слушатель `fullscreenchange` на `document` | `removeEventListener` в cleanup |
| `pages/game/hooks/useCanvasDraw.ts` | подписка `matchMedia` на изменение DPR/зума | `removeEventListener` + корректная переподписка |
| `pages/profile/hooks/useIsOffline.ts` | слушатели `online` / `offline` на `window` | `removeEventListener` в cleanup |
| `widgets/profile-view/ui/ProfileView.tsx` | `URL.createObjectURL` для превью аватара | `URL.revokeObjectURL` + флаг `cancelled` |
| `pages/profile/ui/ProfilePage.tsx` | асинхронная загрузка профиля | флаг `cancelled` отсекает setState после unmount |

### Замечание (не утечка)

В `GamePage.tsx` слушатель `fullscreenchange` оборачивается ref-флагом
`isEventListenerSet`. На утечку это не влияет (cleanup корректно снимает
слушатель), но паттерн хрупкий: при двойном вызове эффектов в `StrictMode` (dev)
слушатель может не переустановиться. Рекомендуется в будущем убрать флаг и
полагаться на стандартный add/remove в эффекте. В рамках задачи по утечкам не
менялось.

## Итог

- Критичных (persistent) утечек памяти не обнаружено.
- Исправлены 3 потенциальные утечки, связанные с отсутствием очистки при
  размонтировании (2× RAF-анимации, 1× обработчики `Image`).
- Остальные подписки/таймеры/слушатели изначально корректно очищаются.
